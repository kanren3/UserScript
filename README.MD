# B 站推流码获取工具

本项目为 Bilibili 直播推流码一键获取与管理的用户脚本，支持一键获取推流码、快速开始/结束直播、分区选择、标题设置等功能。

## 安装方法

点击下方链接直接安装脚本（推荐使用 [Tampermonkey](https://www.tampermonkey.net/) 插件）：

👉 [GreasyFork 脚本安装地址](https://greasyfork.org/zh-CN/scripts/536798)

## 功能介绍

- 一键获取 B 站直播推流码
- 支持二级分区选择、直播标题设置与横屏／竖屏开播
- 推流码一键复制
- 直播状态管理（开播前预检、开关播签名、服务器状态读回）
- 自动保存上次填写内容

## 使用说明

1. 安装脚本后，访问任意 B 站页面右下角会出现悬浮按钮，点击即可打开推流码获取面板。
2. 先登录 B 站。打开面板会查询当前账号的直播间；房间 ID 也可留空自动查询，手动填写时必须是本人的真实房间 ID。
3. 选择二级分区、填写标题并选择横屏／竖屏，点击“获取推流码并开始直播”。脚本会检查房间状态、实名认证、标题和封面；封面或认证未完成时请前往官方直播中心处理。
4. 将服务器地址和推流码复制到 OBS 等推流软件；平台确认开播不等于媒体连接成功或观众已能播放。直播结束后点击“结束直播”，脚本会读回服务器状态。
5. 遇到身份验证时使用官方二维码或链接完成验证。60024／60028 的验证查询可取消，通过后需手动再次点击开播，重新预检与签名；60043 单独引导到官方验证流程，不把 voucher 当作表单参数，也不伪造 Gaia Cookie。
6. 开播请求超时、断网或响应无法解析时不会自动重发，而是查询房间状态。若查询也失败，将保留“结果未知”并禁用开播；重新打开面板查询，或到官方直播中心确认。平台已确认开播但缺少推流地址时仍可结束直播。

## 1.15 协议修复

- 按 [startLive 跨语言实现说明](startLive_跨语言实现说明.md) 的 LiveHime **8.8.0.11119** 契约构造请求：保留空 `access_key`，横屏 `type=2`、竖屏 `type=1`，双 CSRF 在开播签名前加入；关播双 CSRF 在签名后加入。
- 使用原始 UTF-8 键排序、精确百分号编码和加盐 MD5，发送最终 ASCII 正文；不再使用旧开播模板或默认发送 `backup_stream`／`src`／`checked`。
- 原生 `buvid` 持久化在用户脚本存储的 `bili_native_buvid`，来源记录在 `bili_native_buvid_source`，与 Cookie 的 `buvid3` 分离。首次匿名请求 `https://data.bilibili.com/gv`；仅 HTTP／网络失败时生成本地 UUIDv4 回退。缓存损坏、正文格式异常和取消请求均停止，不静默替换设备标识。
- **浏览器适配边界**：用户脚本无法读取系统进程 PID，本地设备回退使用小写 UUIDv4 + `0user`，其中 `0` 是明确的浏览器适配值，并非真实 PID；该回退的当前线上接受情况未验证。有效缓存会持续复用。
- 按服务端顺序选择 RTMP／RTMPS 候选；`new_link` 使用原始 URL 匿名请求，保留编码和凭据，不追加公共签名参数。支持已识别的 RTMP 地址文本及 `addr`／`code`、`rtmp`、`protocols` JSON 结构；调度失败时尝试该候选的直接地址及后续候选。未知结构明确报错，不拿 `live_key` 当推流码。
- 完整开播业务响应保存在用户脚本存储的 `bili_last_start_response`，包含认证 voucher、协议／备流列表等原始字段；它与推流信息均可能包含敏感凭据，请勿公开分享。旧协议响应字段参考：[直播间管理接口](https://github.com/pskdje/bilibili-API-collect/blob/968b3e246f146ef560c05468e200cb5c1f0daaac/docs/live/manage.md)。

## 开发验证

使用 Node.js 内置测试运行器，无需安装依赖：

```sh
node --test startlive.test.cjs
```

回归覆盖文档中可确定输入的横屏／竖屏／`src=7` 签名向量、编码与 MD5 分块边界、设备初始化、开关播不同签名集合、并发点击、预检失败、结果未知与媒体地址选择。

已使用本地模拟 HTTP 响应在 Chromium 运行真实脚本，检查横竖屏、复制、关播读回、无媒体地址、超时、60043、60028 取消、预检拦截及匿名调度；加载现有 QRCode 库后确认身份验证二维码正常显示。未使用真实账号调用开关播接口，未验证 Tampermonkey 实际发出的 Cookie／受限请求头、当前线上风控或媒体推流。双屏、备流和付费业务开播不在此普通开播契约范围内。
